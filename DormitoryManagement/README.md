# نظام إدارة طلبة الأقسام الداخلية — جامعة المثنى

العام الدراسي محفوظ لكل طالب، ويظهر في التسجيل والقوائم والتقارير مع التصفية حسب السنة.
راجع [آلية السنوات الدراسية وترحيل السجلات القديمة](docs/academic-years.md).

أضيفت مستمسكات الطالب إلى التسجيل والتعديل، مع معاينة داخلية وحفظ ضمن النسخ
الاحتياطية. راجع [دليل مستمسكات الطالب](docs/student-documents.md).

تطبيق Windows أصلي باللغة العربية واتجاه RTL مبني على Python وPySide6 وSQLAlchemy وSQLite.
تستخدم الواجهة خط IBM Plex Sans Arabic بأوزان Regular وMedium وSemiBold، وهو مضمّن
في الحزمة للعمل دون إنترنت. بقي خط التقارير مستقلًا للحفاظ على توافق الطباعة واستخراج النصوص.
تظهر الأزرار غير المتاحة بالرمادي، ويُبرز إطار واضح الزر المحدد بلوحة المفاتيح.
تلتف الأسماء الطويلة في جداول الطلبة ومعاينة النتائج مع ضبط ارتفاع الصف، وتظهر الهواتف
والسنوات والأرقام باتجاه مناسب دون تغيير قيمها أو الأصفار الأولى.
يعمل على جهاز واحد دون خادم أو متصفح أو حسابات مستخدمين، ويشمل تسجيل الطلبة، وإدارة البنايات والغرف،
البحث والتصفية، وتقارير Excel وPDF بالأعمدة المختارة، والنسخ الاحتياطي والاستعادة.
التسكين حسب الغرفة وسعتها؛ لا يوجد نظام أسرّة أو حسابات مالية.

هذه النسخة مستقلة داخل `DormitoryManagement`. لا تُعدّل ملفات Django/MySQL القديمة أو قواعد بياناتها،
ولا تستوردها تلقائياً. `start-local.cmd` في المجلد الأب يخص النسخة القديمة.

مصدر النسخة القديمة وأدلتها محفوظان في [legacy/django](../legacy/django/README.md).
قواعد بيانات التشغيل والمستمسكات والنسخ الاحتياطية ليست جزءاً من مستودع GitHub.
لشرح المجلدات وأماكن تعديل الشاشات والخدمات راجع
[هيكل المشروع](../docs/project-structure.md) و[دليل التطوير](../docs/development.md).

## التشغيل الجاهز

فك ضغط حزمة `AlMuthannaNative-Windows` كاملة إلى مجلد دائم، ثم افتح
`AlMuthannaNative\AlMuthannaNative.exe`. لا تنقل ملف EXE وحده بعيداً عن `_internal`.
يمكن تشغيل `CreateDesktopShortcut.cmd` لإنشاء اختصار عربي على سطح المكتب.
راجع [دليل التثبيت والتشغيل](docs/installation.md).

تُنشأ قاعدة البيانات تلقائياً في:

```text
%LOCALAPPDATA%\AlMuthannaDormitoryNative\db.sqlite3
```

لا يحتاج مستخدم الحزمة إلى تثبيت Python. لا تحتوي الحزمة على قاعدة التشغيل أو بيانات الطلبة.
البرنامج يحفظ البيانات عند إغلاقه وإعادة فتحه؛ حدّث ملفات التشغيل في مجلد منفصل واترك مجلد AppData محفوظاً.

## التشغيل من المصدر على Windows وVisual Studio Code

ثبّت Python **3.12 أو 3.13** بمعمارية Windows x64، ثم افتح مجلد `DormitoryManagement` في VS Code.
في الطرفية:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe main.py
```

يمكن استبدال `-3.13` بـ`-3.12` إذا كان هذا هو الإصدار المثبت.
لا تحتاج تفعيل البيئة أو تغيير سياسة PowerShell؛ استدعاء Python بالمسار المباشر يكفي.
للتشغيل اللاحق افتح `start.cmd` في هذا المجلد أو `start-native.cmd` في المجلد الأب؛ يفضّل المشغّل الحزمة المبنية
داخل `dist` إن وجدت، وإلا يشغّل المصدر من البيئة المحلية. أثناء التطوير استدعِ `python.exe main.py` مباشرةً لرؤية تعديلات المصدر قبل إعادة بناء EXE.
اختر المفسر `.venv\Scripts\python.exe` في VS Code.
تنزيل الاعتمادات يحتاج الإنترنت مرة واحدة، أو ملفات wheel موثوقة مجهزة مسبقاً؛ التشغيل اليومي والتقارير لا يحتاجان الإنترنت.

## الاختبارات والبناء

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe tools\build_windows.py
```

أو افتح `build_windows.bat`. تظهر ملفات التشغيل في `dist\AlMuthannaNative` والحزمة وSHA256 في `releases`.
البناء محلي على Windows وبـPython 3.12 أو3.13. افحص EXE الناتج فعلياً ولا تعتبر نجاح تشغيل المصدر دليلاً كافياً على الحزمة.
مثال تحقق على قاعدة تجريبية منفصلة:

```powershell
& '.\dist\AlMuthannaNative\AlMuthannaNative.exe' --smoke-test --data-dir '.\.tools\exe-check' --result '.\.tools\exe-check.json'
```

## البيانات المرجعية

تتضمن الحزمة 19 محافظة و150 قضاء ضمن تغطية جزئية موثقة، و17 كلية و35 قسماً/مسمى تسجيل موثقاً.
**لا تمثل قائمة مكتملة لكل التقسيمات الإدارية أو أحدث الأقسام الجامعية.** تظل الأقسام غير المؤكدة فارغة
إلى أن تعتمد شؤون الطلبة مسمياتها وتضيفها من الإعدادات؛ لم تُنشأ أقسام وهمية لتجاوز النقص.
راجع [المصادر وحدود التغطية](docs/reference-sources.md).

تفاصيل التصميم في [بنية التطبيق](docs/architecture.md)، ونتائج التحقق ومراحل التنفيذ في [تقرير التنفيذ](docs/phase-report.md).

## النسخ الاحتياطي

من الإعدادات اختر إنشاء نسخة احتياطية واحفظها خارج مجلد البرنامج، ويفضل نسخة إضافية على وسيط منفصل.
تستخدم العملية SQLite Backup API؛ لا تنسخ ملف قاعدة مفتوح أثناء الكتابة يدوياً.
الاستعادة تطلب التأكيد، وتتحقق من سلامة النسخة، وتحفظ نسخة أمان قبل استبدال البيانات وإعادة تحميل الواجهة.
استعد ملفات هذا البرنامج الموثوقة فقط؛ قواعد Django القديمة ليست نسخاً متوافقة مع هذه البنية.

## تنسيق التقارير والمعاينة الأصلية

تشمل خيارات التقارير عنواناً قابلاً للتعديل ومعلومات المرشحات والعدد والتاريخ، وحجم خط PDF واتجاه الصفحة،
ومعاينة PDF داخل البرنامج، وورقة ملخص وتنسيق طباعة Excel، وتسلسلاً اختيارياً، وثلاثة قوالب جاهزة وحفظ قوالب محلية،
وحقول توقيع فارغة واسم ملف مقترح بالتاريخ. تبقى البيانات والأعمدة من اختيار المستخدم.
تظل التقارير بحجم A4، وتظهر عناوين وبيانات جدول الطلبة في سطر واحد لكل خلية، مع ضبط النص تلقائياً ليتسع داخل الأعمدة.
تبدأ واجهة التقارير بمعاينة النتائج، وتجمع التصفية وإعدادات الكشف والأعمدة في أقسام واضحة، مع أزرار التصدير في أعلى الصفحة.
راجع [دليل تنسيق التقارير](docs/report-formatting.md). لا تُضاف شعارات أو أختام أو توقيعات رسمية مفترضة.

## بيانات الطلبة المستوردة

تظهر السجلات المستوردة الناقصة في إدارة الطلبة بحالة واضحة، وتبقى الحقول الغائبة فارغة
لتُستكمل بالمعلومات الصحيحة. تحتفظ شاشة «بيانات الملف السابق» بقيم المصدر للقراءة فقط؛
لا تتحول الغرف القديمة إلى تسكين حالي تلقائياً. راجع [دليل السجلات المستوردة](docs/student-import.md).
