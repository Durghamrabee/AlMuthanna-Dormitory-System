# نظام إدارة الأقسام الداخلية – جامعة المثنى

تطبيق Django بواجهة عربية RTL يعمل محلياً على جهاز Windows واحد. قاعدة البيانات
`db.sqlite3`، وجميع ملفات الواجهة والخطوط والرسوم محفوظة محلياً. لا يحتاج MySQL
ولا اتصالاً بالإنترنت أثناء الاستخدام. قواعد MySQL القديمة وبيانات دخولها لم تُحذف.

النسخة المكتبية الحالية دون متصفح موجودة في [DormitoryManagement](../../DormitoryManagement/README.md)،
وتُشغّل بواسطة `start-native.cmd` في جذر المشروع أو ملف EXE الخاص بها. تعليمات `start-local.cmd` أدناه
تخص نسخة Django القديمة المحفوظة مستقلة ببياناتها.

## التشغيل اليومي

**النسخة المكتبية الحالية:** افتح `start-native.cmd`، وراجع
[دليلها](../../DormitoryManagement/README.md). تفاصيل تمييز ملفات النسختين وترتيبهما في
[هيكل المشروع](../../docs/project-structure.md).
التعليمات التالية تخص نسخة Django القديمة.

شغّل `start-local.cmd` ثم افتح **http://127.0.0.1:8000**.

هذا الدليل والأوامر التالية تخص مجلد `legacy/django/`. يمكن تشغيل الملف الموجود
هنا مباشرةً أو استخدام `start-local.cmd` في جذر المشروع. يبحث المشغّل عن بيئة محلية
هنا، ثم يعيد استخدام بيئة `.venv` القديمة في الجذر. مفسر النسخة المكتبية منفصل
ولا يستخدم لتشغيل مكتبات النسخة القديمة.
اترك النافذة مفتوحة أثناء الاستخدام، وأوقف الخادم بـ Ctrl+C قبل إغلاق الجهاز أو الاستعادة.

الوضع المحلي بدون تسجيل دخول مفعّل في إعدادات هذا الجهاز. يتيح هذا الوضع إدارة
جميع السجلات لمستخدم الجهاز؛ لا توجد صلاحيات فردية ما دام مفعلاً. لإعادة الحسابات:
غيّر `DJANGO_LOCAL_NO_LOGIN=false` داخل `.env` ثم أعد تشغيل النظام. لا تنشر الخادم
على شبكة أو تستخدم `0.0.0.0` في هذا الوضع.

## الوظائف المنفذة

- ملفات الطلبة، البحث والتصفية والتسجيل الدراسي السنوي والصور والمستندات الخاصة.
- الكليات والأقسام والسنوات الدراسية ومتطلبات المستندات القابلة للإعداد.
- مجمع ← بناية ← طابق ← غرفة ← سرير، مع الحالات التشغيلية والإشغال المشتق من التخصيصات.
- طلبات سكن: مسودة، تقديم، مراجعة، قبول/رفض، إلغاء، وسجل كامل للحالات والمسؤولين.
- تخصيص سرير، تأكيد الدخول، النقل، الإخلاء وتحرير السرير، وتجديد لسنة أخرى مع حفظ التاريخ.
- المخالفات والإجراءات الإدارية، والصيانة مع تاريخ الحالات وتاريخ الإنجاز.
- لوحة متابعة بأرقام فعلية وستة رسوم Chart.js وبدائل جداول قابلة للقراءة.
- أربعة عشر تقريراً قابلاً للتصفية، وتنزيل Excel وPDF عربي، وعرض مناسب للطباعة.
- نسخ ZIP من الواجهة تشمل قاعدة البيانات والمستندات وبصمات التحقق، وتنبيه دوري قابل للإعداد.
- تسجيل الدخول والخروج، تغيير/استعادة كلمة المرور محلياً، أدوار ونطاقات جنس وبناية وسجل تدقيق.

تفاصيل الاستخدام: [دليل العمليات](docs/operations.md).

## إعداد Windows جديد / Visual Studio Code

المتطلبات: Python 3.12+ مع pip وvenv (تم التحقق هنا باستخدام 3.14.4)، ومتصفح
Microsoft Edge لإنشاء PDF. لا تحتاج خادم قاعدة بيانات أو مكتبات GTK/Pango.
يتطلب تنزيل الاعتماديات إنترنت مرة واحدة؛ التشغيل اليومي محلي بالكامل.

```powershell
# إذا لم يكن py متاحاً استخدم المسار الكامل لمفسر Python المثبت.
py -3.14 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/configure_local.py --no-login
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py setup_roles
.\.venv\Scripts\python.exe manage.py verify_database
.\start-local.cmd
```

في VS Code اختر Python: Select Interpreter ثم `.venv\Scripts\python.exe`.
مساعد الإعداد يولّد سراً عشوائياً عند غيابه ويحفظه محلياً، ولا يعرض قيمته ولا يستبدل
كلمات مرور MySQL القديمة. `.env` وقاعدة البيانات والمستندات والنسخ غير متتبعة في Git.
أبقِ `DJANGO_DEBUG=false`؛ وضع `DJANGO_LOCAL_HTTP=true` يسمح HTTP على loopback فقط.

للاستخدام بالحسابات، عطّل وضع عدم تسجيل الدخول ثم نفّذ:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

لا توجد كلمة مرور افتراضية. إنشاء/تعديل الموظفين من مدير النظام فقط. نطاقات الجنس
والبنايات تمنح صراحةً؛ إنشاء الدور وحده لا يمنح وصولاً. راجع
[المصادقة والصلاحيات](docs/phase-2.md).

## النسخ الاحتياطي والاستعادة

من **النسخ الاحتياطي** اختر «إنشاء نسخة» ثم نزّل الملف واحفظ نسخة خارج الجهاز.
التذكير الافتراضي كل 7 أيام، ويمكن تغييره من إعدادات النظام. النسخة لا تتضمن `.env`
أو رسائل الاستعادة؛ احتفظ بالإعدادات السرية بطريقة خاصة منفصلة.

لنسخة قاعدة بيانات فقط:

```powershell
.\.venv\Scripts\python.exe manage.py backup_database
```

لا تُنسخ قاعدة حية بواسطة النسخ العادي لملف SQLite. الأمر يستخدم SQLite Backup API.
لا تستعد ملفاً غير موثوق. للتحقق من نسخة ZIP وفكها إلى **مجلد استعادة جديد**:

```powershell
.\.venv\Scripts\python.exe manage.py prepare_restore --source backups\bundle-CHOSEN.zip --destination recovery\chosen
```

استبدل CHOSEN باسم النسخة التي اخترتها. بعد نجاح التحقق:

1. أوقف كل نوافذ تشغيل التطبيق وبرامج تصفح SQLite.
2. احتفظ بنسخة من مجلد `private_media` الحالي قبل إرجاع المستندات القديمة.
3. نفّذ الأمر التالي؛ يحتفظ تلقائياً بنسخة أمان من قاعدة البيانات الحالية ويلغي الجلسات القديمة:

```powershell
.\.venv\Scripts\python.exe manage.py restore_database --source recovery\chosen\db.sqlite3 --confirm-stopped
```

4. انسخ محتويات `recovery\chosen\private_media` إلى `private_media` إذا كان مجلد المستندات موجوداً
   في النسخة. لا تحذف ملفاتك الحالية لمعالجة مشكلة ترحيل. الملفات الإضافية غير المشار إليها لا تُنشر.
5. نفّذ `migrate` ثم `setup_roles` ثم `verify_database` قبل إعادة التشغيل.

الاستعادة عملية إدارية خارج الواجهة أثناء توقف التطبيق؛ زر النسخ لا يستبدل البيانات الحية.
تفاصيل القيود والاختبارات: [التسليم والتحقق](docs/delivery.md).

## الاختبارات والتحقق

```powershell
.\.venv\Scripts\python.exe manage.py check --database default
.\.venv\Scripts\python.exe manage.py migrate --check
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
.\.venv\Scripts\python.exe manage.py verify_database
.\.venv\Scripts\python.exe manage.py test tests --verbosity 2
```

تستخدم الاختبارات قاعدة مستقلة `test_db.sqlite3`؛ لا تشغّلها باسم قاعدة المستخدم.
اختبارات PDF الفعلية تحتاج Edge محلياً، وتُعلن أنها متجاوزة إذا لم يوجد محرك متوافق.
SQLite كاتب واحد، و`select_for_update` لا يوفر أقفال صفوف فيه؛ التطبيق يستخدم معاملات
`IMMEDIATE` قصيرة وقيوداً فريدة. لا توجد مطالبة بمساواة تزامنه بتزامن MySQL.

## ملاحظات تشغيلية

- المحجوز لا يعني أن الطالب دخل السكن؛ تأكيد الدخول إجراء مستقل.
- النقل والتجديد يحفظان التخصيص السابق ولا يحذفانه. لا تُحسب الحركة الداخلية كدخول فعلي جديد في الرسم الشهري.
- فتح السنة الدراسية يخص تقديم الطلبات؛ إغلاق التقديم لا يبطل طلباً مقبولاً سابقاً.
- طلب الصيانة لا يعطّل السرير تلقائياً. غيّر الحالة التشغيلية عند الحاجة، بعد نقل أي ساكن أو إخلائه.
- تقارير PDF محدودة بـ 2000 سجل، وExcel بـ 20000 سجل، مع رسالة واضحة لطلب تضييق التصفية عند التجاوز.
- لا توجد واجهة حذف دائم للسجلات التاريخية. تُحفظ العلاقات بواسطة PROTECT وقيود قاعدة البيانات.
- حفظ التقرير/النسخ لا يرسل بيانات لأي جهة؛ المخرجات تتضمن معلومات إدارية خاصة ويجب حفظها محلياً بشكل منضبط.

## النسخة المكتبية والميزات الإدارية

راجع [تثبيت Windows المستقل](docs/windows-desktop.md) لتشغيل الحزمة دون تثبيت Python أو Visual Studio Code.
بيانات النسخة المكتبية محفوظة منفصلة عن ملفات البرنامج، ولا تنقل الحزمة بيانات المشروع تلقائياً.
يمكن نقلها بنسخة ZIP احتياطية واستعادتها من نافذة التشغيل.

أضيفت خريطة الغرف والأسرّة، واقتراحات التسكين، واستيراد الطلبة من Excel بمعاينة وتأكيد،
ونماذج السكن والتعهد والنقل والإخلاء، وتنبيهات قابلة للضبط. التفاصيل في [دليل العمليات](docs/operations.md).
لبناء الحزمة من المصدر: ثبّت `requirements-build.txt` ثم شغّل `python scripts/build_windows.py`.
